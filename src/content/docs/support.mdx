The questions that come up while installing Biryar and in the first
weeks of using it, each with a short answer and a link to the page that
goes further. If yours is not here, write to
[info@ciyalabs.com](mailto:info@ciyalabs.com?subject=Biryar%20support).

Words you do not know are explained in [Words used here](/words/).

## Installing

### Windows says `docker` is not recognized

In full, PowerShell prints "The term 'docker' is not recognized as the
name of a cmdlet, function, script file, or operable program." On a Mac
or Linux the same thing reads `docker: command not found`.

It means the computer does not know the `docker` command yet. Nothing is
wrong with Biryar, and the file you downloaded is fine. It is one of
three things:

- **Docker is not installed.** It is a separate program, and it comes
  first. [Get Biryar, step 1](/get/#step-1-install-docker) has the steps.
- **Docker was installed after this window was opened.** Close the
  PowerShell window and open a new one.
- **Docker was installed and Windows has not been restarted since.**
  Restart, then start Docker Desktop from the Start menu.

Then check, in a new PowerShell window:

```powershell
docker --version
```

Once that prints a version number, go back to your `biryar` folder and
run `docker compose up -d` again.

### Windows says it cannot find `dockerDesktopLinuxEngine`

The message ends "open //./pipe/dockerDesktopLinuxEngine: The system
cannot find the file specified", and usually begins by asking whether the
Docker daemon is running. Docker is installed, and it is not running yet.

Open **Docker Desktop** from the Start menu, wait until it says its
engine is running, and run the same line again. To have it start with
Windows, switch on "Start Docker Desktop when you sign in" in its
settings, under General.

### Docker Desktop will not install, or will not start

Docker Desktop is made by Docker, not by us, and it has requirements of
its own, listed on [its install page](https://docs.docker.com/desktop/setup/install/windows-install/).
Docker's page for every kind of computer is linked from the
[install guide](/setup/install/#dockers-own-instructions-for-each-kind-of-computer).
The usual causes on Windows:

- **Virtualization is switched off.** Docker needs it, and on some
  laptops it is off in the computer's own setup screen (the BIOS or
  UEFI). The Task Manager shows it: under **Performance, CPU**, look for
  "Virtualization: Enabled".
- **WSL is missing or out of date.** Open PowerShell as administrator,
  type `wsl --install`, and restart. To bring an older one up to date,
  `wsl --update`.
- **Windows is too old.** Docker Desktop needs a current Windows 10 or
  Windows 11. Run Windows Update first.

If the installer shows a message, the exact wording is what tells these
apart. On Linux, if `docker ps` says "permission denied", add yourself to
the `docker` group and sign in again.

### Where is the sealing key, and do I need to do anything with it?

Biryar made it on the first start and keeps it on the `biryar-keys` volume.
The one thing to do is back it up somewhere that is not this machine:

```bash
docker compose exec api cat /keys/sealing-key
```

Without it, a backup of the database holds Amazon credentials nobody can
read. To move to a new machine, put the saved key in a `.env` beside the
compose file as `BIRYAR_SECRET_KEY=v1:…` before the first start there.

### Port 8000 is already in use

Set `BIRYAR_PORT` in `.env` to a free port, for example `8001`, and start
again. The interface then answers at that port.

### The sign-up page asks for a setup code

Paste this line into a terminal on the computer Biryar runs on
(PowerShell on Windows) and press Enter. It works from any folder:

```
docker exec biryar-api-1 python -m biryar.init --setup-code
```

It answers `Setup code:` followed by the code.

The first person to sign up becomes the owner, and the code is what keeps
that from being whoever finds the page first. The [install
guide](/setup/install/#your-account) explains the reasoning.

### "No module named 'biryar'"

You typed `python -m biryar.init --setup-code` by itself, as an older
version of the sign-up page said to. Biryar runs inside Docker, so the
line has to be sent there. Put `docker exec biryar-api-1` in front of it,
as in the answer above.

### I forgot my password or my username, or lost my phone

Nobody can email you a reset link, because Biryar runs on your computer
and not on ours. You get back in on the computer Biryar runs on, by
pasting one line into a terminal. There is nothing in it to change:

```bash
docker exec -it biryar-api-1 biryar-password
```

It shows the accounts on that computer, so a forgotten username is
covered, then lets you choose a new password or set up a new phone.
[Getting back in](/setup/getting-back-in/) goes through it step by step,
including how to open a terminal and how to do it without one.

### Updating

```bash
docker compose pull && docker compose up -d
```

The database is updated as Biryar starts. An update that fails changes
nothing and stops with the reason in `docker compose logs api`.

### Biryar does not open after the computer was restarted

Biryar comes back by itself once Docker is running. On Windows and Mac
that means Docker Desktop has to be started; you can have it start when
you sign in, under its General settings. Give it a few seconds, then see
[after the machine restarts](/setup/install/#after-the-machine-restarts).

### Where is my data, and how do I back it up?

On the computer Biryar runs on, and nowhere else: see
[Where your data lives](/methodology/your-data/). A backup is one command,
typed in the `biryar` folder:

```bash
docker compose exec db pg_dump -U biryar biryar > biryar-backup.sql
```

Keep the sealing key with it (`docker compose exec api cat
/keys/sealing-key`): without that key, the Amazon credentials in a backup
cannot be read.

## Connecting Amazon

### Amazon answers `invalid_client`

The application's Client ID or Client secret, entered under **Settings,
Connections**, does not match the application you authorised. Both come
from your own application in the Solution Provider Portal, under its LWA
credentials, and both are needed even when you connect by pasting a token:
the token is exchanged for a one-hour access token before every read, and
Amazon checks that exchange against the application. Enter them again
with "Change the application". [Connecting Amazon](/setup/sp-api/) walks
through it with screenshots.

### The connect button says it is unavailable, or Amazon answers `MD9100`

A private application has no consent page, so the button route cannot
work for it; Biryar says so rather than failing halfway through. Connect
by pasting the refresh token from the Solution Provider Portal instead, as
[Connecting Amazon](/setup/sp-api/) shows.

### I want to see real figures before registering anything

Download a settlement report from Seller Central (**Reports, Payments, All
Statements**, as Flat File V2) and drop it on the Portfolio page. Biryar
reads it, shows the period's revenue and what Amazon kept, and stores
nothing.

## Sourcing

### What do "needs ScraperAPI" and "no key needed" mean?

Every shop in the list says one or the other. **No key needed** means
Biryar reads the shop directly. **Needs ScraperAPI** means the shop turns
programs away, so Biryar reads it through ScraperAPI, a paid service you
hold your own account with. Five of the shops Biryar ships with need no
key. [ScraperAPI](/setup/scraperapi/) lists them all.

### Biryar says my ScraperAPI credits are used up

Then nothing is wrong with the shop or with Biryar: the ScraperAPI account
has no credits left. Top it up, or wait for its monthly refill. Shops kept
running by themselves try again once an hour and carry on from where they
stopped. Shops marked "no key needed" are not affected.

### I set a shop to run several times a day and nothing happened

Three things to check under **Settings, Sourcing**. The retailer has to
be switched on; you have to press **Save changes**, because nothing
changes until you do; and keeping shops running by themselves is part of
Pro. The first pass starts within a minute or two of saving, and the
Sourcing page shows it in the card called **Running by itself**.
[Sourcing](/guide/sourcing/#shops-that-keep-running-by-themselves)
explains the rules.

### A shop says it refused Biryar

Biryar says honestly that it is a program when it reads a shop (see
[the bot page](/bot/)). Some shops answer only to browsers and refuse
everything else, and Biryar does not pretend to be one. Those shops are
marked **needs ScraperAPI**. Add a key under **Settings, Connections**.

### A scan found nothing

Each retailer's line on the Sourcing page says how much it read and why it
stopped. The usual reasons: the shop's prices are not below Amazon's after
the real fees; Keepa does not carry what the shop sells; a key ran out of
tokens or credits; or the scan read only part of a large shop, in which
case the next scan carries on from where this one stopped.
[Sourcing](/guide/sourcing/#why-a-scan-stopped) lists every reason and
what to do about it.

### Do I need Keepa? And how many tokens will I use?

For sourcing, yes: every barcode a scan finds is looked up on Amazon
through Keepa, one token each, and the key goes under **Settings,
Connections**. The Portfolio and the repricer do not need it. Under
**Settings, Sourcing**, the note **What this schedule costs** shows how
many tokens a day your schedule spends against what your Keepa plan
refills. See [Keepa](/setup/keepa/).

### What is the Keepa link beside a deal for?

It opens that product's page on Keepa, with the history of its price and
sales rank on Amazon. A deal is a fact about today's prices, so it is
worth a look before buying: a price that has only just risen may fall
back.

### Do I have to leave the computer on?

For scheduled work, yes. Biryar runs on your computer and can only scan or
reprice while it is awake. Many sellers run it on a small always-on
computer at home. When a computer wakes up, Biryar picks up where it
stopped and does not start again.

## Profit figures

### Profit is blank, or says "needs buy prices"

Biryar will not guess what a unit cost you. Until every sold unit has a
buy price on file, net profit is left blank rather than counting the
unpriced ones as free, and the Portfolio page names the products that are
missing one. Upload a supplier invoice, type a price under a product, or
import a list; [Portfolio](/guide/portfolio/#giving-biryar-your-buy-prices)
shows how.

### The profit on a deal is lower than other tools show

Because Biryar uses what Amazon actually took from your own settled sales,
as a rate plus a flat amount per unit, and on cheap items the flat part
dominates. A tool that uses the headline referral percentage alone will
call a deal profitable that is not. [How the fees are
measured](/methodology/fees/) shows it with figures and a chart.

## Repricing

### Nothing is being sent to Amazon

Three things must all be true: you are on Pro, sending prices is switched
on under **Settings, Repricing**, and the listing itself is turned on, on
the Repricing page. The page says which one is missing. Until all three
hold, every decision is still made, explained and checked with Amazon, so
you can see exactly what would happen.

### How often does it run?

On the schedule you set under **Settings, Repricing**: every 15 minutes,
every hour, every four hours, or once a day. Each pass reads your
catalogue from Amazon, then prices every listing you turned on; the page
shows a pass as it runs and when the next one is due.
[Repricing](/guide/repricing/) explains how the safe band and the position
inside it are decided.

### The Repricing page says "Queued"

The pass is waiting its turn and starts by itself. Repricing has its own
place in the queue, so a long Sourcing scan does not hold it up; a wait of
more than a minute or two usually means another repricing pass is still
running.

### A price is "waiting for you"

That listing has moved more than 8% from its first price of the day, so
the next move needs your say. It is on the Repricing page under **Waiting
for you**, with Approve and Reject. Approving lets the next pass make one
move, at a price worked out then.

### A price moved and I did not want it to

A price never leaves the floor and ceiling set in Seller Central, and a
listing that has moved more than 8% in a day waits for your approval before
moving again. Turn the listing off on the Repricing page, or switch sending
off under **Settings, Repricing**; decisions keep being recorded, and none
is applied.

## Licences

### Biryar says the licence does not check out

It was changed between being sent and being pasted, usually by a line
break or a missing character at the end. Paste the whole line again from
the email. If it still fails, write to us with the licensee name, never
with the licence itself.

### Biryar says to update

The licence was signed with a key this version of Biryar does not know
yet. `docker compose pull && docker compose up -d` brings the version that
does.

### The licence ended

Nothing is deleted. Listings, decisions, scans, results and schedules all
stay. Prices are no longer sent and scheduled work stops; a renewed licence
picks up exactly where the old one left off. See [Free and Pro](/plans/).

## Reaching us

[info@ciyalabs.com](mailto:info@ciyalabs.com?subject=Biryar%20support). We
answer within two working days.

It helps to say which version you run and what Biryar printed around the
time of the problem. Both come from the `biryar` folder:

```bash
docker compose images api
docker compose logs api
docker compose logs worker
```

Never put your sealing key, a licence or a file called `.env` in an
email.
